# Ant2 v2.4.1 → v2.4.3 Session Notes

Working session covering WAF test script overhaul, CRS rule scope analysis, custom rule development, and multi-server deployment.

## Abstract

Three test cases in `owaps.ps1` consistently returned HTTP 200 (WAF bypass) at PL4. Root cause analysis revealed the test payloads were never matched by the claimed CRS rules — each rule targets a different attack surface than what was being tested. Custom ModSecurity rules were written to block the original payloads, baked into `modsecurity-engine.conf` globally, and shipped in v2.4.2. A subsequent deployment to 192.168.0.238 exposed a CRS activation gap in `install.sh` for upgrade scenarios — fixed in v2.4.3.

## Key Takeaways

- **CRS rule 933110** only inspects `FILES` and `X-Filename` headers (multipart upload context) — a plain GET param `?file=shell.php` is never examined by this rule at any paranoia level.
- **CRS rule 933120** checks ARGS for PHP *configuration directive names* (`allow_url_fopen`, etc.) — file extension patterns like `shell.php.jpg` are not in scope.
- **CRS rule 921110** is HTTP Request Smuggling detection, not open redirect — it matches embedded HTTP method patterns (`GET /path HTTP/1.0`) in the request body.
- **NGINX `return 301`** in the port 80 server block executes before ModSecurity phase 1 — any payload sent over HTTP never reaches the WAF.
- **curl URL globbing** silently corrupts NoSQL payloads containing `[...]` unless `-g` (`--globoff`) is passed.
- **install.sh upgrade gap**: when `/opt/modruls_crs/` exists from an old install with `crs-setup.conf.example` but no `crs-setup.conf`, the old code path skipped extraction entirely, leaving the WAF broken.

## Notable Details

### Test Script Bugs Fixed

| Bug | Symptom | Fix |
|-----|---------|-----|
| No `https://` enforcement | 301 on every test | Reject with error if not `https://` |
| curl missing `-g` flag | NoSQL tests → empty HTTP code | Add `-g` to all curl calls |
| Host Header test wrong | Plain `Host: evil.com` never triggers 921160 | Use `Host: evil.com%0d%0aX-Injected:evil` |
| 400 not counted as PASS | Host CRLF block returns 400 | Add 400 to PASS code list |
| 3 wrong payloads | HTTP 200 on 933110/933120/921110 | Custom rules + restore original payloads |

### Custom Rules Added (global, all hosts)

```
id:9500101  PHP extension in ARGS      \.ph(?:p[0-9]?|tml|ar)(\s*$|%00)
id:9500102  PHP double extension ARGS  \.ph(?:p[0-9]?|tml|ar)\.[a-z]{2,4}($|%00)
id:9500103  Open redirect in ARGS      ^https?://[^/]  +  param name matches redirect/url/return/...
```

Location: `nginx-waf/modsecurity-engine.conf` — included by every per-host config file.

### install.sh Fix (v2.4.3)

Added `elif` branch and post-deploy container safety net:
```bash
elif [ -f "${CRS_HOST_DIR}/crs-setup.conf.example" ]; then
  cp "${CRS_HOST_DIR}/crs-setup.conf.example" "${CRS_HOST_DIR}/crs-setup.conf"
fi
# post-deploy: fix inside container if still broken
docker exec ant2proxy-waf cp crs-setup.conf.example crs-setup.conf && nginx -s reload
```

## Gaps / Unanswered Questions

- Custom rules 9500101–9500103 use `deny` action; in `DetectionOnly` hosts they log but do not block — this is correct behavior but should be documented per-host in the UI.
- Open redirect rule 9500103 will block any app that accepts external URLs in `redirect=` params — potential false positive for OAuth callback flows.
- ModSec v3 missing operator list not fully enumerated for CRS v4.26.
