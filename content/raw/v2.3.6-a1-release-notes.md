## Release: v2.3.6-a1 (2026-05-06)

Cumulative release notes covering three patch versions. Live server: 172.20.20.181.

---

## v2.3.5 — CRS Fix + Ant2 Branding

### Bug Fixes
- **CRS install missing `.conf` extension**: The CRS seed script wrote rule files without `.conf` extension, causing ModSecurity to skip them. Fixed seed script to use `.conf`.
- **nginx status feedback**: inotify watcher now writes reload result to `nginx-status.json` for API polling.
- **CRS pre-check**: Installer now checks CRS tarball exists before building nginx-waf image.

### Branding
- Rebranded UI from generic "Nginx Proxy Manager" to **Ant2 Proxy Security Manager**.
- Server: 172.20.20.181 running live.

## v2.3.6 — Rate Limiting, Country Block, Magento WAF, Server Header

### New Features

#### Magento / Adobe Commerce WAF Preset
- Added `[CMS] Magento / Adobe Commerce` as first entry in WAF Settings preset dropdown.
- Excludes rules: 941100–941380, 942100–942430, 933100–933150, 921180, 920230, 920420, 911100, 931130.
- Custom rules: excludes `form_key` (CSRF token) from injection checks, whitelists `product[description]` and `content` fields, allows REST API methods.
- File: `api/src/wafPresets.js`.

#### Ant2 Config Tab (Settings)
- New **Ant2 Config** tab in Settings page (terminal icon).
- Editable `nginx-ant2-custom.conf` — global http-level directives outside virtual host configs.
- **nginx -t** test button: runs `docker exec ant2proxy-waf nginx -t` via Docker socket and shows output.
- API routes: `GET/PUT /api/settings/nginx-custom`, `POST /api/settings/nginx-test`.
- Requires Docker socket mounted: `- /var/run/docker.sock:/var/run/docker.sock:ro` in `docker-compose.yml`.
- File: `api/src/routes/settings.js`, `web/src/pages/Settings.jsx`.

#### 429 Too Many Requests Custom Error Page
- Added 429 to all error page systems:
  - `api/src/services/nginxConfig.js` — `buildErrorPagesBlock` codes list.
  - `api/src/routes/errorpages.js` — `VALID_CODES` and `PAGE_META`.
  - `web/src/pages/Settings.jsx` — `EP_CODES`, `EP_COLORS`, `EP_TITLES`.
- Color: `#f59e0b` (amber). Title: "Too Many Requests".

### Bug Fixes

#### CSP Header Breaking Magento RequireJS
- Removed `Content-Security-Policy` header from `block_exploits` in `nginxConfig.js`.
- Root cause: CSP was missing `'unsafe-eval'` which is required by Magento's RequireJS loader.
- Only kept: `X-Robots-Tag: none` and `Permissions-Policy: interest-cohort=()`.

#### error_page 403 Conditional (WAF on/off)
- `buildWafBlockedPage(wafActive)` now only adds `error_page 403 /waf-blocked.html` when WAF is active.
- When WAF is off, upstream 403 responses now pass through to the user instead of being replaced by the WAF block page.

#### Rate Limiting Format Normalization
- nginx `limit_req_zone` requires `rate=10r/s` format, not `10/s`.
- Added `normalizeRate()` function in `nginxConfig.js`: `100/m → 100r/m`, `10/s → 10r/s` (idempotent).
- Applied in both POST and PUT handlers in `api/src/routes/hosts.js`.
- UI input `100/m` now works correctly.

### Infrastructure

#### Hide `Server: nginx` Response Header
- Added `ngx_http_headers_more_filter_module` to nginx-waf Docker build.
- The module is compiled from source alongside `ngx_http_geoip2_module` in the same `./configure` run.
- `nginx-waf/Dockerfile`: added `headers-more-nginx-module` git clone and build step.
- `nginx-waf/nginx.conf`: added `load_module modules/ngx_http_headers_more_filter_module.so` and `more_clear_headers 'Server'` (after `server_tokens off`).
- Verified: `curl -sI http://localhost:80` returns no `Server:` header.

## v2.3.6-a1 — WYSIWYG Editor Fix

### Bug Fix: Error Pages Editor Shows Real Page Background

**Problem**: The error page HTML editor used a `contentEditable` div inside the app's white-background UI. Error pages have dark gradient backgrounds (`background:linear-gradient(135deg,#0f172a,#1e293b)`), but the editor showed everything on white — colors, gradients, and div backgrounds looked wrong.

**Root cause**: `contentEditable` div inherits the host app's CSS. It cannot render a full `<html>/<body>` page including its own `<style>` block, `background-image`, or gradient.

**Fix**: Replaced `contentEditable` div with an `<iframe sandbox="allow-same-origin">` using `document.designMode = 'on'`. The iframe renders the complete error page HTML (including `<head>`, `<style>`, body background) exactly as visitors see it.

**Details**:
- `web/src/components/HtmlEditor.jsx` fully rewritten.
- **Visual mode**: iframe with `designMode = 'on'` — true WYSIWYG, shows real background.
- **HTML mode**: raw textarea with dark-themed code editor.
- **Visual/HTML toggle** button added to toolbar.
- `overflow:hidden` override injected during editing (stripped on Save) so full page background is visible in the fixed-height editor iframe.
- `key={editing}` added to HtmlEditor in Settings.jsx to force clean remount when switching between error pages.
- Toolbar execCommand calls now target `iframe.contentDocument` instead of the main document.

**Deployment note**: web `Dockerfile` uses `COPY dist/` (pre-built Vite output). Must run `npm run build` locally before rebuilding the web Docker image. This is handled by `build-package.ps1`.
