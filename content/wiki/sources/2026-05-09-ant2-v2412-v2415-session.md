# Ant2 v2.4.12–v2.4.15 Session

Feature work spanning v2.4.12–v2.4.15: jail pipeline speed tuning, post-jail 423 counting, 3-tier attack counter UI, automated block page wording, owaps.ps1 rewrite with SECURE/BROKEN/JAILED categories, owaps.exe compilation, SQLi comment bypass threshold fix, and 3-server deploy.

## Abstract

After v2.4.11 fixed the lazy-ingestion bug, the next problem was pipeline speed: an attacker could fire ~30 s of unblocked requests before auto-jail activated. Intervals were halved (30 s → 10 s). A new `countPostJailHits()` function was added to count 423 responses from nginx access logs (since post-jail requests never reach ModSecurity). The UI gained a 3-tier counter showing jailed-at count, WAF hits after jail, and HTTP 423 blocks. The 423 block page wording was updated from "manually applied" to automated threat detection language. The owaps.ps1 pentest script was rewritten with clear SECURE/BROKEN/JAILED categories and compiled to a standalone `.exe`.

## Key Takeaways

- **Halving poll intervals to 10 s** reduced worst-case jail latency from ~60 s to ~20 s. Further reduction requires architectural changes (event-driven instead of polling).
- **post_jail_count requires access log parsing** — not waf_events — because the nginx geo block fires before ModSecurity. Redis file-position watermarks (`jail:access_pos:{filename}`) enable incremental reads without re-scanning entire log files.
- **The `reason` field is a snapshot store** — `"Auto-jailed: 11 attacks"` preserves the at-jail count so the UI can compute `WAF hits after jail = attack_count - jailed_at`.
- **Pentest results of `423` are not WAF PASS or FAIL** — they are "JAILED" (unverifiable). The pentest rate should exclude JAILED and REDIRECT from both numerator and denominator.
- **owaps.exe via PS2EXE** — wraps PowerShell script into standalone 33 KB Windows executable. PSGallery requires interactive prompt; workaround is direct GitHub download of ps2exe.ps1.
- **SQLi `--` comment (rule 942110) is WARNING (+3 pts)** — threshold 5 never blocks it; threshold 3 does. Per-host threshold is the correct lever, not changing paranoia level globally.
